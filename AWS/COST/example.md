# データ配信構成におけるAWSコスト試算と構成選定報告書

## 1. 概要

システムからユーザーへデータを提供する機能において、「API Gateway + Lambdaから直接データを返却する構成」**と**「S3／CloudFrontを介して署名付きURLにより返却する構成」のコストおよび技術的実現性を比較試算したものです。

---

## 2. 試算の前提条件

本試算では、以下の利用規模およびインフラ条件をベースとしています。

### システム利用条件・データ仕様

* **月間アクセスユーザー数:** 2,000 人
* **1ユーザーあたりの1日平均API実行回数:** 5 回 / 日
* **月間総リクエスト数:** $2,000\text{人} \times 5\text{回/日} \times 30\text{日} = \mathbf{300,000\text{ 回/月}}$
* **データサイズ（元データ）:** **5 MB**
* **データサイズ（圧縮後データ）:** **1 MB** (Gzip / Brotli等)
* **API形式:** 全パターン共通で **REST API**（API Gateway + Lambda）を実行

### 為替レートおよび単価条件（東京リージョン想定）

* **為替レート:** $1\text{ USD} = \mathbf{160\text{ 円}}$
* **API Gateway (REST API) 単価:** $4.25 / 1,000,000 リクエスト
* **S3 Standard ストレージ単価:** $0.025 / GB / 月
* **S3 Standard GETリクエスト単価:** $0.00037 / 1,000 リクエスト
* **S3 Standard PUTリクエスト単価:** $0.0047 / 1,000 リクエスト
* **AWS アウトバウンドデータ転送単価（インターネット宛）:**
* 最初の 100 GB / 月： **無料**（常時無料枠）
* 100 GB 超過分： **$0.114 / GB**
* **Amazon CloudFront 単価:**
* データ転送アウト： 毎月 **1 TB (1,000 GB) まで無料**（常時無料枠）
* リクエスト数： 毎月 **1,000 万リクエストまで無料**（常時無料枠）

---

## 3. 検討パターン一覧

全パターン共通で、ユーザーはREST APIを呼び出します。レスポンスとして「データそのもの」を返すか、「署名付きURL」を返して別ルートで取得させるかの違いとなります。

* **パターンA：API Gateway + Lambda から直接返却（圧縮通信）**
* REST APIのレスポンスボディで1MB（圧縮後）のバイナリデータを直接返却する構成。
* **パターンB：S3 署名付きURL（直接ダウンロード）**
* REST APIでS3の署名付きURLを返却し、クライアントがS3から1MB（圧縮後）のデータを直接取得する構成。
* **パターンC：CloudFront + S3 署名付きURL（CDN経由ダウンロード）**
* REST APIでCloudFrontの署名付きURLを返却し、クライアントがCloudFront経由で1MB（圧縮後）のデータを取得する構成。

---

## 4. 各パターンの詳細コスト試算と計算式

### パターンA：API Gateway + Lambda から直接返却

API Gateway経由で1MBの圧縮バイナリデータを返却します。バイナリ返却のためBase64エンコードが発生し、転送量は実質 **約 1.33 MB** に増加します。

* **月間データ転送量計算式:**

$$
\text{月間転送量} = 300,000\text{ 回} \times 1.33\text{ MB} \div 1,024 = \mathbf{389.65\text{ GB}}
$$

* **内訳と計算式:**

1. **REST API リクエスト料金:**

$$
\left( \frac{300,000\text{ 回}}{1,000,000} \right) \times \$4.25 = \mathbf{\$1.28}
$$

2. **API Gateway アウトバウンド転送料金:**

$$
(389.65\text{ GB} - 100\text{ GB（無料枠）}) \times \$0.114 = \mathbf{\$33.02}
$$

3. **Lambda 実行料金:** 無料枠内（$0.00）

### **合計コスト（月額）:**

$$
\mathbf{\$34.30} \quad (\text{日本円: } \$34.30 \times 160 = \mathbf{\mathbf{5,488\text{ 円/月}}})
$$

---

### パターンB：S3 署名付きURL（直接ダウンロード）

API実行時にLambdaがS3の署名付きURLを発行して返し、ユーザーはS3から1MBの圧縮ファイルを直接GETします。

* **月間データ転送量計算式:**

$$
\text{月間転送量} = 300,000\text{ 回} \times 1\text{ MB} \div 1,024 = \mathbf{292.97\text{ GB}}
$$

* **内訳と計算式:**

1. **REST API リクエスト料金:**

$$
\left( \frac{300,000\text{ 回}}{1,000,000} \right) \times \$4.25 = \mathbf{\$1.28}
$$

2. **S3 GET リクエスト料金:**

$$
\left( \frac{300,000\text{ 回}}{1,000} \right) \times \$0.00037 = \mathbf{\$0.11}
$$

3. **S3 アウトバウンド転送料金:**

$$
(292.97\text{ GB} - 100\text{ GB（無料枠）}) \times \$0.114 = \mathbf{\$22.00}
$$

4. **S3 ストレージ料金:** 5MB保持 $\approx \mathbf{\$0.00}$

### **合計コスト（月額）:**

$$
\mathbf{\$23.39} \quad (\text{日本円: } \$23.39 \times 160 = \mathbf{\mathbf{3,742\text{ 円/月}}})
$$

---

### パターンC：CloudFront + S3 署名付きURL（推奨構成）

API実行時にCloudFrontの署名付きURLを発行して返し、ユーザーはCloudFront経由でデータをダウンロードします。

* **月間データ転送量計算式:**

$$
\text{月間転送量} = 300,000\text{ 回} \times 1\text{ MB} \div 1,024 = \mathbf{292.97\text{ GB}}
$$

* **内訳と計算式:**

1. **REST API リクエスト料金:**

$$
\left( \frac{300,000\text{ 回}}{1,000,000} \right) \times \$4.25 = \mathbf{\$1.28}
$$

2. **CloudFront 転送・リクエスト料金:**

* 転送量 292.97 GB $\le$ 1,000 GB (無料枠内) $\rightarrow \mathbf{\$0.00}$
* リクエスト数 30万回 $\le$ 1,000万回 (無料枠内) $\rightarrow \mathbf{\$0.00}$

### **合計コスト（月額）:**

$$
\mathbf{\$1.28} \quad (\text{日本円: } \$1.28 \times 160 = \mathbf{\mathbf{205\text{ 円/月}}})
$$

## 6. 技術評価および推奨構成の結論

### 1. パターンA（直接返却）が不可となる理由

* **6MB制限の制約:** API GatewayおよびLambdaには「レスポンスペイロード上限 6MB」の仕様が存在します。この制限は**Gzip圧縮後のサイズではなく、圧縮前（またはBase64エンコード後）のデータサイズ**に対して適用されます。
* 本要件では元データが5MB〜6MB前後であり、将来的にデータサイズがわずかに拡張しただけでも `413 Payload Too Large` エラーが発生し通信が切断される致命的なリスクがあります。

### 2. 結論および選定理由

本プロジェクトにおいては **「パターンC：CloudFront + S3 署名付きURL構成」** を採用することを強く推奨いたします。

1. **圧倒的なコスト優位性:**
   CloudFrontの常時無料枠（毎月1TB転送、1,000万リクエスト）が適用されるため、実質的に**REST APIの実行費用（約205円/月）のみ**で運用可能です。
2. **データ制限の完全回避:**
   S3 / CloudFront から直接ダウンロードさせるため、API Gatewayの6MB制限の影響を全く受けません。
3. **ブラウザ自動解凍とユーザー体験の向上:**
   S3オブジェクトに `Content-Encoding: gzip` メタデータを付与して配置することで、転送量を1MBに抑えつつ、ユーザーのブラウザ側で自動解凍されて元データ（5MB）として扱われるため、最速のレスポンスを実現できます。
